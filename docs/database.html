Data

The database

PROTO's knowledge base is published as two Turtle files — a small TBox (schema) and an ABox (instance data) generated from the project's shared spreadsheet — both versioned in the GitHub repository and downloadable below. The combined graph is also published live on TriplyDB as the proverbs-kr dataset, with a working public SPARQL endpoint.

Identifiers

Since v1.1 every IRI points to the real file on GitHub, replacing the placeholder http://example.org/proto#. Classes and properties live in the schema namespace; proverbs, lessons, domains, situations and links live in the data namespace. The data file declares itself an ontology and imports the schema, so opening it alone (for example in Protégé, File → Open from URL) also loads the classes and property types.

Release notes · October 2026

What changed in v1.1

Version 1.1 answers the six points of feedback we received after the project presentation. The proverbs and the 48 links are the same as in v1.0.

  • Resolvable IRIs. The ontology and all its elements are now identified by the GitHub raw-file IRIs listed above, with separate namespaces for schema and data.
  • The knowledge graph imports the schema. proto_data.ttl has an ontology header with owl:imports, so the property types are no longer missing when the data is read on its own.
  • Property types. All 14 properties are declared in the schema as object or datatype properties. groundedIn deliberately has no range, because its values are Wikidata entities outside the ontology.
  • Restrictions and disjoint classes. The six classes are pairwise disjoint, EquivalenceType is a closed list of four distinct values, six properties are functional, and Proverb and CrossCulturalEquivalence carry cardinality restrictions. A reasoner now reports wrong data, such as a proverb typed as a lesson or a link with two types. See the constraints.
  • Complete annotations. Title, description, authors, dates, license, version and citation are inside the ontology header, and every class, property and equivalence type has an English label, a definition and an example. The WIDOCO documentation was regenerated from them.
  • Tested on real texts. PROTO was used to describe 11 proverb uses in 9 news, blog, forum and social media texts, which led to a proposed extension for targets and stance. See the evaluation.
  • Language codes. hasLanguage now uses ISO 639-1 codes throughout: en, fa, it, sq (previously ita and alb).

Not changed: the analyst's reclassification of the links is still a proposal (see the review below), so the published types remain the script's output.

Analyst review of the 48 equivalence links

The conversion script only compares source-domain tags for equality, so it can only ever produce DirectMatch or SameLessonDifferentImage. Polyxeni read all 48 links by hand — original text, translation, and situation of use together — and reclassified several. None of this has been applied to the graph yet: the reclassification is still a proposal, kept here for transparency rather than presented as done. The team has since settled the open questions from the review (see the decisions below).

What the review found

  • The machine under-counts similarity: it missed the Italian–Albanian "after the rain, the sun" pair as a direct match purely because one tag says "Storm" and the other "Rain."
  • Two of the six tacit lessons actually bundle two distinct ideas each — "Actions over intentions" mixes "deeds over words" with "a foolish friend does harm," and "Group vulnerability" mixes "weakest point" with "contagion." 11 of the 48 links join proverbs across these sub-lessons. The team decided not to split the lessons: the six lessons stay, and the sub-lesson is recorded in the notes.
  • Image and pragmatic use can diverge: English, Italian and Albanian all use "quiet water," but the English proverb praises quiet people while the Italian and Albanian warn against them — a reminder that SituationOfUse, not just SourceDomain, belongs in any equivalence comparison.
  • Where languages converge, it's often shared textual transmission rather than independent invention — e.g. the seeker/finder image in Farsi, Italian and Albanian likely traces to Matthew 7:7.

False-friend candidates (not yet links in the graph)

The generation script never assigns FalseFriend because it only links proverbs that already share a lesson. Reading across lessons for a shared image surfaces these:

Team decisions on the review's open questions

  • Lessons: not split. The six lessons stay, with the sub-lesson recorded in the notes.
  • Persian and Italian readings: confirmed.
  • Competency questions: the analyst's eight SPARQL queries are adopted as the project's competency questions.
  • Reclassification: not applied to the published graph in this release. It is listed as future work, and the published types (5 / 43 / 0 / 0) are the script's output.

Example queries

Illustrative SPARQL queries — useful starting points, distinct from the project's formal competency questions. Run them against the live public SPARQL endpoint on TriplyDB, or load the .ttl files above into a local triplestore (Apache Jena Fuseki, GraphDB, RDFLib).

Every proverb that teaches "Determination / Perseverance"

PREFIX proto: <https://raw.githubusercontent.com/callmesevda/KR-Project/main/proto-ontology-structure.ttl#>

SELECT ?proverb ?text ?language WHERE {
  ?proverb a proto:Proverb ;
           proto:hasLesson ?lesson ;
           proto:hasText ?text ;
           proto:hasLanguage ?language .
  ?lesson proto:hasLabel "Determination / Perseverance" .
}

Proverb pairs that are a "direct match" (same lesson AND same imagery)

PREFIX proto: <https://raw.githubusercontent.com/callmesevda/KR-Project/main/proto-ontology-structure.ttl#>

SELECT ?proverbA ?proverbB ?note WHERE {
  ?equiv a proto:CrossCulturalEquivalence ;
         proto:hasEquivalenceType proto:DirectMatch ;
         proto:linksProverbA ?proverbA ;
         proto:linksProverbB ?proverbB ;
         proto:hasDivergenceNote ?note .
}

Source domains used by more than one proverb

PREFIX proto: <https://raw.githubusercontent.com/callmesevda/KR-Project/main/proto-ontology-structure.ttl#>

SELECT ?domain (COUNT(?proverb) AS ?nProverbs) WHERE {
  ?proverb proto:hasSourceDomain ?domain .
}
GROUP BY ?domain
HAVING (COUNT(?proverb) > 1)
